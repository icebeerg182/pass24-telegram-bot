# Навык Яндекс Алисы для заказа пропусков

Голосовой заказ пропусков через тот же аккаунт PASS24, что и Telegram-бот.

**Пример:** «Алиса, закажи пропуск пасс24 мазда шесть пять шесть» → пропуск Mazda 656 на ваш адрес.

Telegram-бот и Алиса — **независимые сервисы** в `docker-compose.yml`: можно поднять только бота или бота + `pass24-alice`.

## Что нужно заранее

- Работающий Telegram-бот (PASS24-логин проверен).
- Для адресов без госномера: `BOT_REQUIRE_FULL_PLATE=false` в `.env`.
- **HTTPS** с публичным URL (Яндекс не принимает `http://` и путь `/health` — нужен webhook с токеном).
- Аккаунт [Яндекс.Диалоги](https://dialogs.yandex.ru/developer) (тот же Яндекс ID, что на Станции).

> **Без своего домена:** можно использовать [sslip.io](https://sslip.io) — `ВАШ-IP-ЧЕРЕЗ-ДЕФИС.sslip.io` (например `203-0-113-10.sslip.io`) и Caddy с автоматическим Let's Encrypt.

## 1. Настройка `.env`

Добавьте в `.env` на сервере:

```env
# Уже есть для бота
PASS24_PHONE=+79XXXXXXXXX
PASS24_PASSWORD=...
PASS24_ADDRESS_KEYWORD=...
BOT_REQUIRE_FULL_PLATE=false

# Новое для Алисы
ALICE_WEBHOOK_TOKEN=сгенерируйте_случайную_строку
ALICE_PORT=8080
ALICE_SKILL_INVOCATION=пропуск пасс24

# Опционально: ограничить по user_id Яндекса (пусто = все, у кого есть навык)
# ALICE_ALLOWED_USER_IDS=
```

Сгенерировать токен:

```bash
openssl rand -hex 24
```

URL webhook для консоли Яндекса:

```
https://ВАШ-ДОМЕН/alice/webhook/ВАШ_ALICE_WEBHOOK_TOKEN
```

## 2. Запуск сервиса

```bash
cd /opt/pass24-telegram-bot
docker compose up -d --build pass24-alice
docker compose logs -f pass24-alice
```

Проверка:

```bash
curl -s http://localhost:8080/health
# {"service":"pass24-alice","status":"ok"}
```

## 3. HTTPS

Яндекс шлёт POST только на **https://**. Варианты:

### nginx

```nginx
location /alice/webhook/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

### Caddy (удобно с sslip.io)

```caddy
ВАШ-IP-ЧЕРЕЗ-ДЕФИС.sslip.io {
    reverse_proxy 127.0.0.1:8080
}
```

Проверка (должен ответить `{"status":"ok"}`):

```bash
curl -s https://ВАШ-ДОМЕН/health
```

**Не подставляйте `/health` в Backend URL навыка** — только полный путь webhook с токеном (см. ниже).

## 4. Создание навыка в консоли Яндекса

1. Откройте [dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer) → **Создать навык**.
2. Тип: **Умения и развлечения** → **Свой backend** (Webhook URL, не «Функция в Облаке»).
3. Вкладка **Настройки**:
   - **Backend URL:** `https://ВАШ-ДОМЕН/alice/webhook/ВАШ_ALICE_WEBHOOK_TOKEN`
   - **Тип доступа:** **Приватный** (для себя и друзей по ссылке).
   - **Хранилище данных** — не включать.
   - **Связка аккаунтов** — **оставить пустой** (PASS24-логин уже на сервере в `.env`).
4. Вкладка **Публикация** — обязательные поля:
   - **Имя навыка** и **имя разработчика**
   - **Активационное имя** — как в `ALICE_SKILL_INVOCATION` (например `пропуск пасс24`)
   - **Примеры запросов:** `закажи пропуск пасс24 мазда 656`, `мазда шесть пять шесть`
   - **Категория**, описание, **иконка** 224×224
   - **Поверхности:** включить **Яндекс Станция** (и Приложение Яндекса для теста)
   - **«Нужно устройство с экраном»** — выключено
5. **Сохранить** → **Опубликовать**. Приватный навык обычно проходит автомодерацию за несколько минут.

На вкладке **Тестирование** отправьте пустой запрос — в ответе должна быть подсказка с примером марки и номера.

## 5. Тест на Станции

На колонке должен быть тот же Яндекс-аккаунт, что в консоли разработчика.

Фразы:

- «Алиса, запусти пропуск пасс24» → подсказка.
- «Алиса, закажи пропуск пасс24 мазда 656» → заказ без подтверждения.
- «Алиса, попроси пропуск пасс24 бмв сто двадцать один» → BMW 121.

Логи на сервере:

```bash
docker compose logs -f pass24-alice
```

## 6. Поделиться с друзьями

1. Навык → вкладка **Настройки** → **Приватный**.
2. Вкладка **Доступ** → **Сгенерировать** ссылку.
3. Отправьте ссылку другу (одна ссылка — один человек).
4. Друг открывает ссылку под своим Яндекс ID → навык появляется на его устройствах.

Все друзья заказывают пропуска на **ваш** адрес PASS24 (один аккаунт в `.env`).

Чтобы ограничить список людей даже при наличии ссылки на навык, задайте `ALICE_ALLOWED_USER_IDS` — `user_id` из логов после первого запроса.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ALICE_WEBHOOK_TOKEN` | — | Секрет в URL webhook (обязательно) |
| `ALICE_PORT` | `8080` | Порт HTTP внутри контейнера |
| `ALICE_HOST` | `0.0.0.0` | Интерфейс привязки |
| `ALICE_SKILL_INVOCATION` | `пропуск пасс24` | Имя в подсказке |
| `ALICE_ALLOWED_USER_IDS` | пусто | Белый список `user_id` Яндекса |
| `BOT_REQUIRE_FULL_PLATE` | `true` | `false` для режима Mazda 656 |

Остальные `PASS24_*` и `BOT_LLM_*` — общие с Telegram-ботом.

## Несколько ботов на одном сервере

Если на хосте несколько копий проекта (разные `.env`), у каждой:

- свой каталог и свой `ALICE_WEBHOOK_TOKEN`;
- в `docker-compose.yml` уникальный `container_name` для `pass24-alice` (например `pass24-alice-site2`);
- отдельный навык в Яндекс.Диалогах или один навык на один backend.

## Безопасность (публичный репозиторий)

**Не коммитьте:** `.env`, `ALICE_WEBHOOK_TOKEN`, пароли PASS24, токены Telegram.

Токен webhook — секрет: любой, кто знает URL, может слать запросы от имени навыка. При утечке сгенерируйте новый `openssl rand -hex 24` и обновите URL в консоли Яндекса.

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| Алиса: «навык не отвечает» | HTTPS, URL в консоли, `docker compose logs pass24-alice` |
| В Backend указан `/health` | Заменить на `/alice/webhook/<токен>` |
| 404 от сервера | Токен в URL совпадает с `ALICE_WEBHOOK_TOKEN` |
| «Не найден госномер» | `BOT_REQUIRE_FULL_PLATE=false` |
| «Не удалось определить марку» | Скажите «мазда», «бмв»; включите `BOT_LLM_BRAND_RESOLVER` |
| «У вас нет доступа» | Уберите или поправьте `ALICE_ALLOWED_USER_IDS` |
| Навык на модерации | Подождать 5–15 мин; приватные навыки обычно проходят быстро |
